# 左右配置のホバー名の表示

## 原因

Custom Dock のホバー名は、`CustomDockPreview.swift` の `DockBar` が `!vertical` の場合にだけ描画していた。左右配置では名前を描かなかった。

左右配置のパネルは Dock 本体の幅（`DockMetrics.barThickness`）しかなく、名前を表示できる余白もなかった。

## 変更内容

左右配置でも、ポインタを重ねた項目の名前を Dock の内側に表示する。左配置では右側、右配置では左側に出す。

- 名前の位置と幅の計算を `DockLabelPlacement` に切り出した。下配置の計算は従来と同じ式になる。
- 左右配置では、名前の縦位置を項目の中心に合わせ、Dock の高さの範囲に収める。幅は最大240ptで、長い名前は末尾を省略する。
- 左右配置のパネルを、名前用の余白（`DockMetrics.sideLabelGutter`、248pt）だけ内側へ広げた。Dock 本体は画面端に寄せたままにする。
- ポインタの判定領域（`interactionFrame`）を Dock 本体だけに絞った。名前用の余白ではマウスイベントを受けず、背後のウィンドウやデスクトップへクリックが通る。
- アクセシビリティラベルは既存のボタンのものを変えていない。名前の Text は従来どおり VoiceOver から隠している。

## 検証

2026-10-17 に、以下を確認した。

| 項目 | 結果 |
| --- | --- |
| Release ビルド（修正前と修正後） | 成功した |
| 自動テスト | `swift test` で93件すべて成功した（`DockLabelPlacementTests` の5件を含む）。`xcodebuild test` でも、`project.pbxproj` を再生成して同じ件数になることを確認した |
| 左右の位置、縦位置の範囲内への補正、幅の上限と余白に収まること | 単体テストで確認した |
| 下配置の位置計算が従来と同じであること | 単体テストで確認した |

GUI は macOS 26.6.2、1600×1000の専用ヘッドレス VM 内で確認した。ホストのデスクトップには、アプリや VM の画面を表示していない。

| 項目 | 結果 |

## 未検証

- 左配置の修正前後の画像と動画は、管理画面を開いたまま撮ったため、管理画面が背後に写っている。
- 右配置の長い名前、画面端に近い項目の名前、項目が多くスクロールする場合は、VM で確認していない。縦位置の補正は単体テストだけで確認した。
- 右配置のクリック透過は、VM で確認していない。
- VoiceOver の読み上げは確認していない。ラベルの実装は変えていない。
- 画像と動画は、キーボードフォーカス中の項目にも名前を出す変更を含むビルドで撮影した。この変更はレビューで範囲外と判断して外した（キーボードでの名前表示は #48 で扱う）。ホバー時の表示は、外した変更の影響を受けない。外した後のビルドでは、VM での撮り直しをしていない。
- 自動非表示、折りたたみ中の判定領域、マグニフィケーションの設定の組合せ、複数ディスプレイは確認していない。
- macOS 15〜25 と、実機での描画は今回の GUI 検証に含まない。
