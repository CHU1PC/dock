# ログイン起動で Studio ウィンドウを開かない

## 変更内容

ログイン起動を示す Apple Event の受信が SwiftUI の起動シーン決定より遅れた場合も、起動後に Studio ウィンドウが残らないようにする。Apple Event ハンドラーは AppKit デリゲートの初期化時に登録し、SwiftUI の初期化前に届いたイベントも保留して起動状態へ反映する。後からログイン起動イベントが届いた場合は、Studio ウィンドウを閉じる。

Studio ウィンドウの自動復元は無効にする。Custom Dock の表示状態は既存どおり保存済みの `dockVisible` に従う。通常起動では Studio ウィンドウを自動表示し、ログイン起動では表示しない。ログイン起動後の Dock アイコン再オープン要求も自動表示として扱わず、メニューバーの「Dock を管理…」から明示的に開ける。

## 仕様判断

- Apple Event が App の状態作成前に届いた場合はデリゲートに保持し、状態作成後に反映する。
- Apple Event が状態作成後に届いた場合は起動状態を更新する。ログイン起動なら既に表示された Studio ウィンドウを閉じる。
- Apple Event が届かない場合は通常起動として扱う。
- Dock の表示は `dockVisible` で決める。ログイン起動で `true` なら Dock のみ表示し、`false` ならどちらも表示しない。
- Studio シーンの自動復元を無効にし、保存されたウィンドウ状態からログイン起動時に再表示される経路を止める。

## 自動テスト

`LoginLaunchPolicyTests` で、通常起動とログイン起動の Dock 表示状態、早着したイベント、遅着イベント、イベント未着時の扱いを検証する。今回の判定ロジックは純粋関数とイベント状態で確認し、実際の Apple Event 到着順や macOS のシーン復元は確認していない。

## 未検証

- 合成 Apple Event と実際のログイン項目の両方で、Studio ウィンドウが起動後に再表示されないこと。
- ログイン起動で Dock の表示状態が `true` と `false` のそれぞれに従うこと。
- 通常起動と、メニューバーからの Studio ウィンドウ表示。
- macOS の起動・アクティベーション・ウィンドウ復元と Apple Event の実際の順序。

## 撮影の手順

専用のヘッドレス macOS VM で確認する。ホストではアプリを起動しない。`DOCKSTUDIO_DATA_DIR` に `profiles.json` と `launch-state.json` を置き、次の各条件で起動する。

1. `launch-state.json` を `{"dockVisible": true}` にし、ログイン項目として起動する。ログイン後に Custom Dock だけが表示され、Studio ウィンドウが表示されないことを記録する。
2. `launch-state.json` を `{"dockVisible": false}` にしてログイン項目から起動する。Dock と Studio ウィンドウのどちらも表示されないことを記録する。
3. 通常起動し、Studio ウィンドウが表示されることを記録する。
4. ログイン起動後、メニューバーの「Dock を管理…」から Studio ウィンドウを開けることを記録する。

画像はログイン起動で Dock のみが表示された状態、Dock を非表示にしたログイン起動の状態、通常起動の状態、メニューバーから Studio を開いた状態を保存する。Apple Event を合成した起動と実ログイン項目の自動起動の両方を試し、起動後少なくとも 34 秒間のウィンドウ状態を記録する。
