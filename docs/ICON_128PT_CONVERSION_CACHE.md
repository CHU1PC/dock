# 128pt アイコン変換とキャッシュ

GitHub issue #74 の実装になる。

## 変更内容

白黒とガラス調のアイコン変換解像度を、実際に表示するサイズと画面の backing scale factor から決める。128pt のアイコンは、2倍表示で通常時に256px、拡大率2倍の表示で512pxになる。画面倍率が2未満でも最低2倍を使う。

変換済み画像のキャッシュ上限を16MiBから32MiBへ増やす。512px の画像は1枚あたり1MiBなので、同じスタイルのアイコンを17個以上表示しても、キャッシュ上限だけが原因で再変換されない容量になる。項目数上限は128枚のままにする。

## 仕様判断

解像度、キー、画像コスト、上限は `DockIconConversionPolicy` の副作用のない関数にまとめた。`ItemIcon` が受け取るポイント数には Dock の拡大率が含まれるため、その値に画面倍率を掛けて変換サイズを得る。

キャッシュキーはファイルパス、スタイル、ガラス調の明暗で作る。解像度はキーに含めない。要求サイズ以上の画像がキャッシュにあれば再利用し、大きなサイズが要求された場合は同じキーの値を高解像度画像に置き換える。これにより、サイズを小さくした後も高解像度画像を使い回せる。

キャッシュコストは RGBA 画像のピクセル数に4バイトを掛けて求める。512px では1,048,576バイトになり、32MiB の上限は同じサイズの画像を最大32枚分保持できる。実際の退避時期は `NSCache` が管理する。

## 撮影の手順

撮影担当は、専用のヘッドレス macOS VM または検証用 Mac で実施する。ホストに Dock Studio や検証用 Dock を表示しない。

### 検証データと起動

ゲストに `/Users/Shared/dockstudio-74` を用意し、そこを `DOCKSTUDIO_DATA_DIR` に指定する。`profiles.json` は同じディレクトリに置く。初回起動後、通常のプロファイル編集画面で比較用の項目を加え、保存された `profiles.json` を撮影に使う。

比較用プロファイルには Finder、Safari、Calculator、Calendar、Contacts、Notes、Reminders、Maps、Messages、Photos、Preview、TextEdit、Music、Podcasts、TV、Freeform、System Settings など、ゲストにあるアプリを17個以上入れる。標準 macOS Dock にも同じアプリを登録する。

Release ビルドをゲストへ配置し、実行ファイルを直接起動する。

```sh
DOCKSTUDIO_DATA_DIR=/Users/Shared/dockstudio-74 /path/to/DockStudio.app/Contents/MacOS/DockStudio
```

### 操作と比較

1. システム設定の「デスクトップと Dock」で標準 Dock のサイズを大きくし、Dock Studio のアイコンサイズ128ptと見た目が近くなるよう調整する。Dock の拡大を有効にする。
2. Dock Studio の設定を開き、アイコンサイズを128ptにする。項目が17個以上見える状態にする。
3. 白黒スタイルを選ぶ。同じアイコンを標準 Dock と Custom Dock の両方に並べる。
4. ガラス調スタイルに切り替え、ライトとダークの双方で同じ比較を行う。
5. 各 Dock で通常表示とポインタを重ねた拡大表示を撮る。特に輪郭の段差、小さな文字や線、細部のぼけを同じアイコン同士で見比べる。
6. 17個以上の項目を表示したまま、ポインタを項目間で数回移動する。アイコンの表示が一時的に標準解像度へ戻る、または移動のたびに変換し直す様子がないか確認する。
7. 画面の backing scale factor と、標準 Dock のサイズ調整に使った設定を記録する。キャッシュ内部の退避は画面だけでは断定せず、観察できた挙動を記録する。

### 期待する結果

128pt、2倍表示では、通常表示の白黒とガラス調が256pxの変換画像を使う。ポインタ拡大で2倍になったアイコンは512pxを使い、輪郭と細部が標準 Dock の同サイズのアイコンと比べて荒く見えない。17個以上を並べても、容量上限だけを理由に同じアイコンの変換が繰り返されない。
