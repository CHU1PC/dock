# 下端の Dock の位置修正

## 原因と修正

下端に配置した Custom Dock の背景は、画面下端から18pt上にあった。配置に使う10ptの余白と、透明なパネル内の8ptの余白が重なっていた。また、標準 Dock の領域を除いた visibleFrame を基準にしていたため、標準 Dock が下側を確保すると、さらに上へ押し上げられる計算だった。

macOS 26.6.2 の VM 内で標準 Dock と比較し、背景の下端を物理画面下端から5ptにそろえた。通常の条件では13pt下がる。背景の位置からパネル内の透明な余白を引き、窓の原点を決める。下端配置の横幅の上限と中央も、物理画面を基準にする。左右配置の計算は変更していない。

## 検証

2026-10-17 に、専用のヘッドレス VM 内で確認した。ホストに検証画面は表示していない。

| 項目 | 結果 |
| --- | --- |
| VM の画面 | 1600×1000、backingScaleFactor 1だった |
| 修正前の背景の下端 | 画面下端から18ptだった |
| 標準 Dock の背景の下端 | 同じ VM の画像では約5ptだった |
| 修正後の背景の下端 | 5ptに合わせた描画を確認した |
| パネルの AX 座標 | 上端の Y が833から846になり、13pt下がった |
| フォーカスを渡した後 | Y は846のままで、窓が上へ押し戻されなかった |
| 自動非表示 | 退避、画面下端付近からの復帰、再度の退避を動画で確認した |
| Release ビルド | 成功した |
| 自動テスト | 76件すべて成功した |

回帰テストでは、標準 Dock の予約領域が0ptと85ptの場合を確認した。原点が負になる外部ディスプレイの座標も使った。修正前は、背景の余白が18ptまたは103ptになってテストが失敗した。修正後は、いずれも5ptで成功した。外部ディスプレイの実接続は検証していない。

修正前、標準 Dock、修正後のスクリーンショットと、約15秒の操作動画を、[画面の記録](media/dock-position/)に保存した。動画は撮影時刻の間隔を維持して15 fpsに変換した。実機の描画性能を測ったものではない。

修正後の画像と標準 Dock の参照画像は、4f540a2のビルドで撮り直した。管理画面と設定画面の画像も、同じ修正後のビルドにそろえた。

## レビューへの対応

今回の修正について、Sonnet のコードレビューを1回実施した。判定は APPROVED で、横幅の上限の基準をそろえる指摘が1件あった。実行時の懸念を含め、以下のように対応した。修正後の再レビューは行っていない。

| 指摘または懸念 | 対応 |
| --- | --- |
| 窓幅は visibleFrame、中央は物理画面で、基準が食い違う | 下端配置の横幅の上限も、物理画面幅から左右10ptを除いた値にそろえた |
| 最下端の5ptは背景の操作範囲に入らない | 背景より外の透明な余白なので、背面へクリックを通す既存動作を維持した。非表示からの復帰範囲は画面下端に届く |
| 非表示から復帰する範囲が狭くなる | 修正後も約13ptの範囲が残る。VM 内で画面下端から8ptの位置へポインタを移し、復帰することを確認した |
| 透明な窓が画面外へ3pt出て、位置が補正される可能性がある | はみ出すのは透明な余白だけになる。VM の AX 座標と実表示で位置を確認し、フォーカスを渡しても変わらないことを確認した |
| 描画の高さと配置計算が一致するか確認が必要になる | パネルの内側の余白を同じ定数にそろえ、実画像で背景の下端を確認した |
