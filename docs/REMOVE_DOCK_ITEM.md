# Dock 項目の取り外し

## 仕様

Custom Dock の項目を右クリックすると、メニューに「Dock から取り外す」が表示される。選ぶと、使用中のプロファイルから項目の参照を取り除き、すぐに保存する。保存後は画面に「<項目名> を Dock から取り外しました」と状態が出る。

元のアプリやファイルには触れない。プロファイルの参照だけを消す。

「実行中のアプリを表示」で一時的に出ている項目は、プロファイルに保持されていないため、メニューにも VoiceOver の操作にも取り外しを出さない。

VoiceOver では、同じ操作をアクセシビリティアクション「Dock から取り外す」として提供する。項目には、メニューを開く AXShowMenu も公開されている。VoiceOver を使わないキーボード操作では、メニューを開く手段がない（検証の節を参照）。

保存処理は `DockStore.removeSavedItem(_:fromProfile:)` として、画面から独立した関数にした。Dock の外へドラッグして取り外す操作（#10）も、この関数を使える。

プロファイルに未保存の編集がある場合は、その編集を保存せずに残し、取り外した項目だけを下書きからも除く。取り外した項目は下書きからも除き、プロファイル編集画面の「取り消し」用の記録も、同じ項目であれば消す。そのため、下書きの保存や取り消しで、取り外した項目が戻らない。

## 検証

2026-10-17 に、以下を確認した。

| 項目 | 結果 |
| --- | --- |
| Debug ビルド | 成功した |
| 自動テスト | 88件すべて成功した。`swift test` と `xcodebuild test` で同数になった |
| 取り外しの保存 | 再読込後も項目が消えており、元のファイルが残った |
| 未保存の下書き | 項目だけが消え、プロファイル名の編集は残った |
| 実行中アプリの一時表示 | 取り外し対象にならず、保存内容が変わらなかった |

GUI は macOS 26.6.2、1600×1000の専用ヘッドレス VM 内で確認した。ホストのデスクトップには、アプリや VM の画面を表示していない。

- 6項目のプロファイルで、Mail を右クリックし、メニューに「Dock から取り外す」が出ることを確認した。
- 選ぶと Mail だけが消え、Dock が詰まった。
- 保存ファイルから Mail が消え、ゲストの `/System/Applications/Mail.app` は残っていた。
- アプリを再起動しても、Mail は戻らなかった。

右クリックの画面と動画は Debug ビルド（SHA-256 は `aa3808ceb66e4bd0de75851e97f5468b2b9134cb54ca4163870f8a52f01d6631`）で撮影した。レビュー対応後の次の AX 検証は、Release ビルド（SHA-256 は `21c02162fb7d915c8fa1942d066a43b9ef991645b6b24cf1c003bf5e5c1a655d`）で行った。レビュー対応後の右クリックの画面と動画は、撮り直していない。

[画面と動画](media/remove-dock-item/)には、取り外し前（`before.png`）、メニュー表示中（`menu.png`）、取り外し後（`after.png`）、再起動後（`after-relaunch.png`）と、一連の操作の動画（`remove-dock-item.mp4`）を保存した。動画は撮影時刻の間隔を維持して15fpsに変換し、倍速にはしていない。VM の撮影であり、実機での描画性能の測定ではない。

### アクセシビリティとキーボード（AX API による確認）

同じ VM で、アクセシビリティ API を直接呼ぶ確認用ツールを使った。出力は[ax-actions.txt](media/remove-dock-item/ax-actions.txt)に保存した。VoiceOver は有効にしていない。

| 項目 | 結果 |
| --- | --- |
| 保持されている項目（Finder、Safari、Mail、Terminal、Calendar、Downloads） | `AXUIElementCopyActionNames` に、カスタムアクション「Dock から取り外す」が含まれた |
| 実行中アプリの一時表示（Calculator など） | 同じ一覧に、このアクションは含まれなかった |
| Mail でアクションを実行 | `AXUIElementPerformAction` が成功し、保存ファイルから Mail が消えた。`Mail.app` は残った。画面には「Mail を Dock から取り外しました」が出た |
| 一時表示のアクションを実行しようとする | 公開されていないため、実行できなかった |
| `AXShowMenu` で右クリックと同じメニューを開く | メニューが開き、「Dock から取り外す」が表示された。画面は[ax-show-menu.png](media/remove-dock-item/ax-show-menu.png) |
| Tab によるフォーカス移動 | Terminal の項目にフォーカスリングが表示された |
| Tab でフォーカスした項目で Control+Return、Control+Space | Terminal が起動した。Control は無視され、メニューは開かなかった |
| Tab でフォーカスした項目で Shift+F10 | 何も起きず、メニューは開かなかった |

結論として、VoiceOver が使うアクセシビリティ API では、取り外しとメニュー表示の両方に届く。VoiceOver を使わず、Tab とキーボードだけで右クリックメニューを開く手段は、今回の実装にはない。試したキーの組み合わせでは届かなかった。受け入れ条件のうち「キーボードでも利用できる」は、VoiceOver のアクションを使う経路に限って満たす。

撮影では、VNC 接続の直後に送った入力が反映されないことがあった。接続から10秒待ってから操作している。これは撮影手順の問題であり、アプリの動作ではない。

## 未検証

| 項目 | 状況 |
| --- | --- |
| VoiceOver を有効にした実操作 | アクセシビリティ API での確認にとどまり、VoiceOver の読み上げとアクションメニューの実操作は確認していない |
| VoiceOver を使わないキーボードだけでの取り外し | 届かない。専用キーは設けていない。Delete キーは誤操作と取り消し手段がないため割り当てていない |
| デスクトップ用パネルの Dock | 同じ `DockBar` を使うが、パネル上のメニューは VM で撮影していない |
| 左右配置、複数プロファイル、macOS 15〜25 | 今回の GUI 検証には含まない |
| 取り外しの取り消し | 設けていない。再追加はプロファイル編集から行う |
