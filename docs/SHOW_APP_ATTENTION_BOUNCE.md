# 他アプリの注意要求によるバウンド

## 仕様

「設定」の「動作」に「他のアプリの注意要求を表示」を追加した。有効な場合、Accessibility がすでに許可されているときだけ、標準 Dock のアプリ項目を観察する。許可を要求するダイアログは出さない。標準 Dock の項目 URL からアプリを特定し、項目の位置が短時間に複数回往復し、他の Dock 項目が動いていない場合に注意要求と推定する。

この方法は間接的な推定になる。要求の種類は識別できず、Dock の拡大や OS の別の動きによる誤検知を完全には除外できない。項目の URL と位置を得られないとき、権限がないとき、またはアプリが Dock に見つからないときは何も表示しない。起動イベント後30秒は、起動時のバウンドとの混同を避けるため抑制する。同じアプリの表示は10秒に1回までとし、位置の動きが1.2秒止まると表示を解除する。

「アニメーションを減らす」が有効なときは、バウンドの代わりにアイコンの周囲を静止したオレンジ色の線で強調する。集中モードの状態を読む公開経路は使っていないため、集中モードに応じた抑制はできない。この機能はシステム通知を作らず、視覚表示だけを行う。必要なら設定をオフにできる。

## 検証

`AttentionBounceTests` で、孤立した繰り返しの位置変化、複数項目の移動、拡大によるサイズ変化、小さな動き、単発の動き、Accessibility 権限、観測不能、起動直後の抑制、頻度制限を確認する。

自動テスト、Release ビルド、build-for-testing の実行結果は作業報告に記録する。実画面の動きと Accessibility 経由での Dock 項目取得は確認していない。

## 未検証

- macOS が注意要求の種類に応じて表示する実際のアニメーションと、検出の遅れ。
- 起動時のバウンド、Dock の拡大、標準 Dock を隠した場合の実際の誤検知と見逃し。
- Dock の項目から `AXURL` と `AXFrame` を得られる条件、ログイン項目や別ユーザー権限のアプリ。
- 集中モードと通知抑制の検出。公開 API で状態を確認する実装は含めていない。
- 「アニメーションを減らす」時の静止した強調の見た目。

## 撮影の手順

1. VM でビルド済みアプリを起動する。`DOCKSTUDIO_DATA_DIR` には、この機能を有効にした `profiles.json` を置いたディレクトリを指定する。
2. Dock Studio の設定画面で「他のアプリの注意要求を表示」を有効にし、システム設定の「プライバシーとセキュリティ」から Dock Studio にアクセシビリティを許可する。
3. 標準 Dock に表示されているテストアプリから注意要求を発生させ、Custom Dock の同じアプリ項目を観察する。起動直後ではなく、起動後30秒以上経過してから要求する。
4. 同じ操作を「アニメーションを減らす」の有効時にも行い、静止したオレンジ色の強調になるか確認する。
5. 標準 Dock と Custom Dock の配置が異なる場合、起動時の動き、拡大操作、標準 Dock の非表示でも誤検知の有無を確認する。

撮影するものは、設定が有効な画面、通常時の注意要求によるバウンド動画、「アニメーションを減らす」有効時の静止表示、標準 Dock と Custom Dock を含む全体画面とする。動きの動画では標準 Dock の要求と Custom Dock の表示が同時に分かるようにする。
