# Spring loading 後のフォルダへのドロップ

## 変更内容

1秒のドラッグホバーで開いたフォルダ項目、またはその内容表示へファイルをドロップすると、Dock項目として登録せず、フォルダへ移動する。フォルダが見つからない場合、または移動先が移動元フォルダ自身かその子孫の場合は拒否する。既存の挿入、アプリで開く、ゴミ箱へ移動する動作はドロップ先の判定を共通化して保つ。

アプリ項目のコンテキストメニューにある「全ウィンドウを表示」は既存の機能になる。`docs/research/WINDOWS_SPACES.md` の調査で実行できた方法に合わせ、標準 Dock のアクセシビリティメニューを開き、その項目を押す実装を維持する。キー入力の合成や非公開 API は使わない。

## 仕様判断

- フォルダへの移動は `FileManager.moveItem` で1項目ずつ行う。名前の衝突や権限エラーが起きても、後続項目の移動を続け、失敗した項目名とシステムのエラー文を表示する。
- 開いたフォルダ内容の表示全体をドロップ先にする。
- 移動元がフォルダで、移動先がそのフォルダ自身または子孫にあたる場合は、循環する配置を防ぐため拒否する。
- プレビューでは実ファイルを移動しない。
- App Exposé の起動方法は既存の標準 Dock メニュー操作を使う。実画面での OS 連携は今回確認していない。

## 自動テスト

`DockDropRoutingTests` は、挿入、アプリで開く、ゴミ箱、使用できないフォルダ、フォルダ自身と子孫への移動拒否を確認する。ファイル移動のテストは衝突時の個別エラーと後続項目の継続を確認する。

2026-10-18 にホストでスクリプトを実行し、398件の単体テストがすべて成功した。Release ビルドと build-for-testing も成功した。

## 未検証

- 実画面での Dock 項目とフォルダ内容表示へのドロップ。
- Finder の実ファイルに対するアクセス許可、名前衝突、外部ボリューム間の移動。
- 標準 Dock の App Exposé との画面上の連携。

## 撮影の手順

撮影は専用のヘッドレス macOS VM 内で行う。Dock Studio を `DOCKSTUDIO_DATA_DIR` に検証用の `profiles.json` が置かれたディレクトリを指定して起動する。

1. 検証用のプロファイルに、テストファイルを入れた既存フォルダを登録する。
2. Finder からファイルを Dock のフォルダ項目へドラッグし、1秒保持して内容を開く。
3. ファイルをフォルダ項目へドロップし、ファイルがフォルダ内へ移り、Dock 項目が増えないことを確認する。
4. 同じ操作を開いた内容表示の上でも行い、ファイルがそのフォルダへ移動することを確認する。
5. 同名ファイルがあるケース、フォルダ自身とその子孫を移動しようとするケースを試し、失敗項目の報告と拒否を確認する。
6. アプリ項目のコンテキストメニューから「全ウィンドウを表示」を選び、標準 Dock の App Exposé が開くことを確認する。

撮影対象は、項目上へのドロップ前後、開いた内容表示上へのドロップ前後、失敗の表示、App Exposé の画面とする。操作が分かる動画も撮影する。
