# Finder の選択項目をサービスから追加する

GitHub issue #140 の実装になる。

## 変更内容

Finder の選択項目を受け取る macOS サービス「Dock Studio に追加」を生成 Info.plist の `NSServices` に登録した。定義は `project.yml` に置き、XcodeGen で再生成しても保持する。ファイル URL と複数選択を受け取り、ファイル、フォルダ、アプリを Dock 項目へ分類して追加する。標準 Dock の Control-Shift-Command-T は登録せず、利用者がシステム設定のサービス一覧で任意のキーを割り当てる。

## 仕様

- サービスは `Info.plist` の `NSServices` に登録し、`NSKeyEquivalent` は指定しない。
- 追加先はサービス実行時に有効なプロファイルとする。追加は保存済みデータに反映し、どのプロファイルを編集中でも下書きには触れない。
- URL はローカルファイルだけを受け入れる。存在しない対象、読み取れない対象、起動ポリシーに反するファイルは追加せず、項目名と理由をエラーに表示する。
- 重複項目は既存の `DuplicateItemPolicy` に従う。保存領域が読み取り専用の場合は変更せず、理由を表示する。
- URL ごとのファイル種別と検証理由を候補に解決し、純粋関数 `FinderSelectionAddition.prepare` が候補を追加対象と拒否対象に分ける。

## 自動テスト

`FinderSelectionTests` で、複数 URL のファイル、フォルダ、アプリ分類、非ローカル URL と存在しない対象の拒否、拒否理由、アクティブプロファイルへの追加、編集中の下書きの保持、読み取り専用データの保護を確認した。2026-10-18 に `swift test` は362件すべて成功し、Release ビルドと `build-for-testing` も成功した。

## 未検証

- Finder のサービス一覧に登録されることと、Finder から実行できることは未確認になる。
- システム設定でサービスにキーを割り当てられること、標準 Dock のキーが維持されることは未確認になる。
- macOS が返す権限不足の URL、実機でのエラー表示と保存結果は未確認になる。
- 実画面の撮影と VM での確認は行っていない。

## 撮影の手順

専任の担当が専用のヘッドレス macOS VM で確認する。ホストではアプリを起動しない。`DOCKSTUDIO_DATA_DIR` には検証用の空ディレクトリを指定し、既定のプロファイルを使う。

### 標準 Dock との比較

1. Finder でファイルを選び、Control-Shift-Command-T が標準 Dock の追加操作として維持されていることを確認する。
2. 同じキーが Dock Studio のサービスに割り当てられていないことを確認する。
3. 標準 Dock への追加前後を撮影する。

### Dock Studio サービス

1. Finder でテキストファイル、フォルダ、アプリを複数選択する。
2. Finder の「サービス」メニューに「Dock Studio に追加」が表示されることを確認する。表示されない場合はシステム設定のキーボードショートカットでサービスを有効にし、任意のキーを割り当てて再確認する。
3. サービスを実行し、有効なプロファイルに各項目が正しい種類で追加されることを確認する。
4. 別プロファイルの編集画面に未保存変更を作り、Finder からサービスを実行する。対象は有効なプロファイルに追加され、編集中の下書きが変わらないことを確認する。
5. 既存項目を再選択して重複が追加されないことを確認する。存在しない対象や実行可能ファイルを渡せる方法があれば、拒否理由が表示されることも確認する。

撮影するものは、サービスメニュー、追加後のプロファイル、下書き編集中の追加前後、重複または拒否のエラー表示、標準 Dock のキー操作が維持された状態になる。Finder からサービスが実行できない場合は、そのメニューの状態と「未確認」の結果を記録する。
