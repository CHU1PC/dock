# 右クリックメニューからウィンドウを前面に表示する

## 変更内容

起動中のアプリ項目に、右クリックメニューとアクセシビリティ操作からウィンドウ一覧を開く項目を追加した。キーボードで開くメニューも同じ `DockItemMenu.kinds` と `actions(for:)` を通り、ウィンドウ名や権限案内は共通モデルで作る。

アプリの項目にだけ「ウィンドウを前面に表示」を出す。通常の「開く」は残し、アクセシビリティ権限がない場合は一覧に案内を表示する。ウィンドウがない場合と一覧取得に失敗した場合は、従来と同じく無効な案内項目を表示する。ウィンドウの上限表示は既存実装にないため追加していない。

## 受け入れ条件との対応

| 条件 | 状況 |
| --- | --- |
| 右クリックメニューに「ウィンドウを前面に表示」を表示する | 満たした（単体テストのみ。ポインタメニューとキーボードメニューで同じ種類を使う） |
| 権限がない場合も「開く」と権限案内を表示する | 満たした（単体テストのみ。共通モデルの案内文を確認） |
| ウィンドウがない場合は空一覧を扱う | 満たした（単体テストのみ。無効な案内項目を確認） |
| 複数のウィンドウ名と最小化状態を表示する | 満たした（単体テストのみ。重複名と最小化表示を確認） |

## 検証

ホストで、ビルドと単体テストだけを実行した。GUI は表示していない。

| 項目 | 結果 |
| --- | --- |
| `swift test` | `Executed 404 tests, with 0 failures (0 unexpected)`、`exit=0` |
| Release ビルド | `** BUILD SUCCEEDED **`、`exit=0` |
| Debug の `build-for-testing` | `** TEST BUILD SUCCEEDED **`、`exit=0` |

## 未検証

- 実際の右クリックメニューとアクセシビリティ操作での表示
- アクセシビリティ許可を求める OS の画面と、許可後のウィンドウ取得
- macOS のバージョンによる表示差

## 撮影の手順

実画面の撮影は行っていない。確認する場合は、専用のヘッドレス macOS VM で行う。

### 検証用データ

`/Users/Shared/dockstudio-187/profiles.json` に TextEdit を含むプロファイルを用意し、`DOCKSTUDIO_DATA_DIR=/Users/Shared/dockstudio-187` を指定して Dock Studio を起動する。アプリ項目の `target` はゲストにある TextEdit のアプリ URL を指定する。

### 操作と期待する結果

1. ゲストで TextEdit を起動して、ウィンドウを2つ開く。
2. Custom Dock の TextEdit を右クリックする。
3. 「ウィンドウを前面に表示」のサブメニューに、2つのウィンドウ名が出ることを確認する。
4. 片方を選ぶと、そのウィンドウが前面になることを確認する。
5. アクセシビリティ権限を許可しない状態では、「開く」が残り、サブメニューに権限案内が出ることを確認する。
