# #173 実画面確認 担当 D の結果

確認環境は、ヘッドレス VM（macOS 26.6.2、画面 1600×1000、システム言語 en-US）の 1 台のみ。アプリは main の `8849979`（実行ファイルの SHA-256 `1d7c9852876b0a3d0d6544bec1e5854f0b9fbbf83c00486ddac46fe73c0bd57c`、ホストとゲストで一致）。macOS 15 と 27、Handoff 相手機器、複数ディスプレイはこの環境に無いため、該当する条件は「確認できず」とした。画面の VNC 取得は遅れることがあり、ログと食い違うときはログを正とした。

## #118 Show All Windows

| 条件 | 判定 | 根拠 |
|---|---|---|
| Dock アイコンから標準 Dock の「Show All Windows」を実行する（macOS 26） | 満たさない | Custom Dock の「全ウィンドウを表示」を Safari と System Settings で実行したところ、どちらも「標準 Dock の「全ウィンドウを表示」を実行できませんでした。この項目は安全のため無効にしました。」で失敗した（`media/verification-173/D/118-expose-failed-alert.jpg`）。標準 Dock のメニュー（Options、Show All Windows、Hide、Quit）は画面に出る（`118-dock-menu-26.jpg`）が、メニューは別プロセス DockHelper のウィンドウで、Dock の項目に AXShowMenu を送っても AXShownMenuUIElement や子要素が返らない（同じ属性を読む別の AX クライアントで、System Settings と Safari の両方で確認）。実装が読む経路ではメニュー項目を見つけられない |
| Safari の項目で URL が一致する | 満たさない | Dock 側の Safari の AXURL は `file:///System/Volumes/Preboot/Cryptexes/App/System/Applications/Safari.app/`。撮影手順の例の `/Applications/Safari.app/` を正規化した結果とは一致しない（別の不具合として、メニューの問題と独立に起きる） |
| Accessibility 許可がない場合の案内 | 確認できず | ゲストでは ssh 経由で起動したアプリが責任プロセス（sshd-keygen-wrapper）の許可を引き継ぎ、常に許可済みになる。LaunchServices 経由の許可なし起動は未実施 |
| 失敗時に項目を安全に無効化する | 満たした | 上の失敗の直後に失敗アラートが出て、以降その項目は無効扱いになる設計どおり（アラート文面で確認。再度のメニュー無効表示の画面は撮っていない） |
| macOS 15 と 26 の比較、英語と日本語 | 確認できず（省略） | macOS 15 の VM が無い。26 のみ英語環境 |

## 後片付け
