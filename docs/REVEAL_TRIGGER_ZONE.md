# 自動で隠れた Dock を表示する反応範囲

## 変更内容

自動で隠れている Dock を表示するマウスの反応範囲を、画面の端の細い帯にした。

| 配置 | 変更前 | 変更後 |
| --- | --- | --- |
| 下 | 画面の下端から16pt（`DockStudio/Services/CustomDockWindowController.swift:40`、`panel.minY - screen.minY + 16`、下端に接するパネルでは16pt） | 画面の下端から2pt |
| 左 | 画面の左端からパネルの内側16ptまで | 画面の左端から2pt |
| 右 | パネルの内側16ptから画面の右端まで | 画面の右端から2pt |

帯の太さは `DockInteractionGeometry.revealZoneThickness`（2pt）で、計算は純粋な関数 `DockInteractionGeometry.reveal(screen:panel:position:)` にある。帯の長さ（下は Dock の幅、左右は Dock の高さ）は従来のままにした。

2pt にした理由は次のとおり。

- 通常のマウス移動で端まで動かせば、ポインタは端のピクセルに届く。2pt は Retina 画面で 4 ピクセルに当たり、端に押し付けたポインタも、端から数ピクセル手前で止まったポインタも拾える。
- 1pt でもよいが、ポインタが端の 1 ピクセル手前で止まる環境の余裕を残した。標準 Dock より高い位置で反応する問題は、2pt では起きない。

表示した後に隠れないようにする範囲は、`DockInteractionGeometry.keepVisible(interaction:screen:position:)` に分けた。従来は反応範囲が 16pt あり、Dock の枠と画面の端の隙間（8pt）をまたいでいた。反応範囲を細くすると、ポインタが隙間で隠れる待ち時間に入ってしまうので、Dock の枠から画面の端までを「表示を保つ範囲」にした。`updateVisibility()` の表示中の判定だけで使う。表示アニメーション、隠すまでの待ち時間、ドラッグ中の表示は変えていない。

## 検証

2026-10-22 にホストで実行した。

| 項目 | 結果 |
| --- | --- |
| `swift test` | `Executed 479 tests, with 0 failures` |
| Release ビルド | `** BUILD SUCCEEDED **` |
| Debug の `build-for-testing` | `** TEST BUILD SUCCEEDED **` |

追加した単体テストは `DockStudioTests/RevealTriggerZoneTests.swift` にある。下、左、右の帯の位置、別の画面（右隣と下隣）の座標、ポインタが端ちょうどにある場合、帯の 1pt 上、Dock の枠の内側と隙間が対象になる。画面の端から 2pt の位置を使っていた `ReviewRegressionTests` の画面追従テスト 2 件は、ポインタを端ちょうどの位置に直した。

## 撮影の手順

専任の担当が、検証用 VM で次を行う。

1. `DOCKSTUDIO_DATA_DIR` に、自動で隠す設定（`autoHide: true`）の検証用データを渡して起動する。配置は下を既定にし、左と右でも繰り返す。
2. Dock が隠れたことを確かめる（キーボードフォーカスは外しておく）。
3. ポインタを、画面の下端から約 20pt 上、約 5pt 上、画面の本当の下端の順に動かす。上の 2 か所では Dock が出ず、下端で出ることを確かめる。
4. 下端で出た後、ポインタを Dock の上、Dock と画面の端の隙間、Dock の外の順に動かす。Dock の上と隙間では出たままで、外に出ると従来の待ち時間の後に隠れることを確かめる。
5. 左と右の配置で、画面の左端、右端について同じ操作を行う。

撮る画像と動画は次のとおり。

- 下端から約 20pt 上にポインタがあり、Dock が隠れたままの画像
- 本当の下端にポインタがあり、Dock が出た画像
- 3 と 4 の操作を続けた動画（ポインタが見えるもの）
- 左と右の配置で、端にポインタがあり Dock が出た画像

## 未検証

- 標準 Dock の反応範囲は測定していない。この変更は「標準 Dock は画面の本当の下端まで行かないと表示されない」という報告に基づき、標準 Dock の値の実測は受け入れ条件に残っている（専用の VM または実機で測る）。
- 実機と VM のどちらでも、GUI でポインタを動かした確認は行っていない。
- 複数の画面を実際に接続した場合の、隣の画面との境界での挙動は、座標の単体テストだけで確認している。
- 端に押し付けたポインタの座標（右端で `maxX` 未満になるか）は、実機で確認していない。
