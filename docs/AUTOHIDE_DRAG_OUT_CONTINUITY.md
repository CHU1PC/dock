# 自動非表示中のドラッグ取り外しを継続する

## 仕様

自動非表示が有効な Custom Dock で項目をドラッグして取り外している間は、ドラッグ状態を Dock の操作中として扱う。ドラッグ中にポインタが Dock から離れても Dock を畳まず、ドラッグ終了後はポインタ位置に応じて元の自動非表示動作へ戻る。

ドラッグ中の状態は `DockDragOutCancellation` が持つ。`CustomDockWindowController` はこの状態を既存の操作中判定へ加え、`DockVisibilityState` がドラッグ中の折り畳みを抑止する。ドラッグ中はポインタが Dock の操作領域を離れてもパネルのマウスイベントを透過させない。メニューやポップオーバーの操作中と同様に、ドラッグ終了後は最後の操作時刻から通常の1秒の待機を経て折り畳みとクリック透過へ戻る。

パネルがキーウィンドウであること自体は、操作中として扱わない。ドラッグ取り外しではクリックでパネルがキーになり、アプリが非アクティブなときは OS がキーを与え直し続けるため、これを操作中に数えるとドロップ後も折り畳みが止まっていた（#191）。キーボード操作（フォーカスのショートカットで入った状態）、メニュー、ポップオーバー、ドラッグだけを操作中とする。この判定は `DockVisibilityState.isInteracting` にある。

自動非表示を無効にしたときの取り外し、通常のホバーやクリック、およびドラッグのキャンセルと取り外し条件は変更しない。

## 受け入れ条件との対応

| 条件 | 状況 |
| --- | --- |
| 自動非表示の有効時と無効時に、外へのドラッグで取り外せるかを確認する | 未確認。専用VMでの画面確認が必要 |
| 自動非表示中、ドラッグ中は Dock が畳まず取り外しを完了できる | 状態遷移とドラッグ中のイベント透過抑止の自動テストを追加した。専用VMでの操作確認は未確認 |
| ドラッグ終了後に自動非表示とクリック透過へ戻り、通常のホバーとクリックを保つ | 自動テストを追加した。専用VMでの画面確認は未確認 |

## 検証

ホストではビルドと単体テストだけを実行する。GUI は起動しない。

| 項目 | 結果 |
| --- | --- |
| `swift test` | 258件、失敗0件（追加したドラッグ中の自動非表示とイベント透過のテストを含む） |
| Release ビルド | 成功 |
| Debug の `build-for-testing` | 成功 |

## 未検証

- 専用VMで自動非表示の有効時と無効時に、ドラッグ取り外しが最後まで完了すること。
- ドラッグ中にウィンドウがドラッグイベントを継続して受け取ること。
- ドラッグ終了後のクリック透過、通常のホバーとクリックの実画面での挙動。
- macOS 15以降の各バージョンでの差。

## 撮影の手順

専用のヘッドレス macOS VM のゲストで実行する。ホストには検証用の画面を表示しない。Dock Studio は、検証用プロファイルを指定して起動する。

### 検証用データ

ゲストで `/Users/Shared/dockstudio-88` を作成し、以下を `profiles.json` として保存する。

```json
{
  "schemaVersion": 1,
  "activeProfileID": "00000000-0000-0000-0000-000000000088",
  "settings": {
    "mode": "custom",
    "position": "bottom",
    "iconSize": 64,
    "autoHide": true,
    "showRunningApps": false
  },
  "profiles": [
    {
      "id": "00000000-0000-0000-0000-000000000088",
      "name": "Drag out continuity",
      "items": [
        {
          "id": "00000000-0000-0000-0000-000000000881",
```

次のように起動する。

```sh
DOCKSTUDIO_DATA_DIR=/Users/Shared/dockstudio-88 /path/to/DockStudio.app/Contents/MacOS/DockStudio
```

### 操作と期待結果

1. 自動非表示を有効にした状態で Dock を画面端から表示する。
2. Calculator を Dock の外へドラッグし、ポインタが画面端の Dock 領域から離れた状態で保持する。Dock が表示されたままで、項目のドラッグ表示が続くことを確認する。
3. Dock から十分離してドロップする。Calculator が Dock から取り外され、ドラッグ終了後は通常の自動非表示待機を経て Dock が畳まれることを確認する。
4. Calculator を Dock に戻すか、検証用プロファイルを初期状態に戻す。
5. 自動非表示を無効にし、同じドラッグを行う。従来どおり取り外せることを確認する。
6. ドラッグ後に残った項目で通常のホバーとクリックを確認する。

### 標準 macOS Dock との比較で測ること

標準 Dock に Calculator と TextEdit を追加し、標準 Dock の自動的に隠す設定を有効にする。同じポインタ操作で、次の時間と挙動を記録する。標準 Dock における取り外しの開始方法やアニメーションの仕様は、ゲストの macOS バージョンの実際の動きに従って記録する。

- 画面端からポインタを入れて、Dock が現れるまでの時間。
- Calculator を Dock の外へドラッグした後、項目が Dock から離れても表示を保つかどうか。
- ドラッグ中に項目の表示やドラッグ操作が途切れるかどうか。
- 項目をドロップしてから Dock が隠れるまでの時間。
- 取り外し後に、別の項目をホバーおよびクリックできるかどうか。

## 実画面の確認の試み（専用ヘッドレス VM、2026-10-18）

コミット `af6ac62` の Release ビルド（SHA-256 `d877f985e92681d7d2ac7a30b2e85d2f80a179f555370eddae109b301fb1bfbd`、ホストとゲストで一致）を、macOS 26.6.2 の専用ヘッドレス VM で試した。**自動非表示での取り外しの連続性は、確認できなかった。**

- 自動非表示を有効にすると、デスクトップ用パネルのウィンドウは `onscreen=false x0 y920 w220 h80` のままになり、ポインタを画面下端（x=100、110、800、960、y=995 から 999）へ合成で動かしても、Dock は現れなかった。このため、手順 1 の「Dock を画面端から表示する」ができず、ドラッグ中の表示維持も、ドロップ後の自動非表示への復帰も、観察できなかった。#85 の撮影でも同じ現象だった（ポインタだけで現れない）。合成ポインタが、反応領域を起こさないためと思われる。
- 自動非表示を無効にした対照の取り外しは、AX で Calculator のボタンの位置が取れず（座標 0,0）、ドラッグが成立しなかった。項目は残った。確認できなかった。
- 標準 Dock の比較は、行っていない。画像と動画は撮っていない（ログのみ: [logs.txt](media/autohide-drag-out-continuity/logs.txt)）。

## #191 の再現と確認（専用ヘッドレス VM、2026-10-19）

Release ビルドに一時ログを入れて、ドロップ後の状態を観察した。Finder を前面にして Dock Studio を非アクティブにし、先頭の項目を y=300 までドラッグして離した。

- 旧コードでは、ドロップ後にパネルが約5秒周期でキーウィンドウになり直した（`NSApplication _handleKeyFocusNotification` 経由、イベント種別 21）。キーの間は `panel.isKeyWindow` が操作中として数えられ、折り畳みが解かれた。パネルは描画されたままの時間が長く、画面差分でも表示を確認した。
- 同じ手順でアプリがアクティブな場合は、ドロップ時にキーが外れて1秒後に隠れた。ポインタを動かさない対照も隠れた。
- 修正後のビルドで同じ手順を3回行い、3回とも35秒後までパネルが隠れたままだった。キーの付け直しは各回で1〜9回起きていたが、折り畳みは解かれなかった。

未検証: アクセシビリティ許可が有る状態、複数ディスプレイ、フォーカスのショートカットでキーボード操作に入った後の折り畳み（自動テストの対象外の実画面）。
