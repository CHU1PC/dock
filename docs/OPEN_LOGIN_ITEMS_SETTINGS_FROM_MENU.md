# Dock メニューからログイン項目の設定を開く

GitHub issue #130 の実装になる。

## 仕様

アプリ項目のコンテキストメニューに「システム設定のログイン項目を開く」を追加した。選ぶと、既存の `LoginItemController.openSystemSettings()` から `SMAppService.openSystemSettingsLoginItems()` を呼び出す。

この操作はシステム設定のパネルを開くだけになる。DockStudio は、対象アプリのログイン項目の登録状態を読み取らず、登録や解除もしない。対象アプリを指定したり、状態を表示したりする操作だと誤解させないよう、メニュー項目は設定パネルを開くことだけを示す。

DockStudio 自身のログイン時起動は、従来どおり「設定」>「一般」の「ログイン時に Dock Studio を開く」で登録・解除する。Dock メニューの案内とは別の操作になる。

## 自動テスト

`DockItemMenu` の単体テストで、案内項目がアプリ項目だけに出ること、表示名が設定パネルを開く表現であること、VoiceOver アクションには追加しないことを確認する。

| `swift test` | 334件すべて成功した（追加分 `HideOthersTests` は1件） |
| Release ビルド | 成功した |
| `build-for-testing` | 成功した |

## 未検証

- macOS のシステム設定パネルが実際に開くこと。
- メニューの表示、位置、操作感。
- 標準 Dock の「ログイン時に開く」との表示や動作の比較。
- macOS 15 以降での差。

## 撮影の手順

撮影は専用ヘッドレス VM のゲストで行い、ホストではアプリを起動しない。検証用データには空のディレクトリを `DOCKSTUDIO_DATA_DIR` に指定し、初回起動で生成された既定プロファイルを使う。

1. 設定の「Dock」で Custom Dock を有効にし、対象のアプリをプロファイルに追加する。
2. Custom Dock の対象アプリを右クリックし、「システム設定のログイン項目を開く」を選ぶ。
3. システム設定の「ログイン項目と機能拡張」が開くことを確認する。DockStudio のメニューに、対象アプリの登録状態や登録・解除の操作が出ないことも確認する。
4. 「設定」>「一般」で、DockStudio 自身の「ログイン時に Dock Studio を開く」が別の設定として表示されることを確認する。
5. 標準 Dock でも対象アプリのメニューを開き、「オプション」>「ログイン時に開く」の表示と動作を記録する。DockStudio の案内項目と標準 Dock の機能を区別して確認する。

撮影するものは、アプリ項目のメニュー、開いたシステム設定のログイン項目パネル、「設定」>「一般」の DockStudio 自身のログイン時起動、標準 Dock の「ログイン時に開く」メニューになる。メニューを開く操作と設定パネルへの遷移は動画にも記録する。
