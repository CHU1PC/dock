# ゴミ箱へのドロップ

GitHub issue #38 の実装になる。

## 変更内容

Dock のゴミ箱にファイルやフォルダをドロップすると、ドロップされた項目だけを `FileManager.trashItem` でゴミ箱へ移動する。永久削除は行わない。各項目を個別に処理するため、一部が失敗しても残りの移動を続け、失敗した項目名と OS のエラーを表示する。権限不足のときは、アクセス許可が必要な可能性をエラーに含める。

ドロップ元のアプリが渡した URL に対して移動を試みる。Full Disk Access を要求する処理や、ゴミ箱の中身を列挙する処理は追加していない。

## 仕様判断

- `FileManager.trashItem(at:resultingItemURL:)` を使い、Finder と同じく元に戻せるゴミ箱への移動を依頼する。
- 成功した項目だけをゴミ箱へ移動し、失敗した URL は残す。複数項目の結果をまとめてエラー表示する。
- 書き込み不可のボリューム、ロック済み項目、ユーザーがアクセスできない場所などの失敗内容は、OS が返す説明を表示する。Full Disk Access の付与は要求しない。
- 設定画面のプレビュー用ストアでは実ファイルを移動しない。

## 未検証

- 専用 VM で Finder から実際にドロップし、元ファイルがゴミ箱へ移り、「戻す」で復元できること。
- ロック済み、権限不足、外部ボリューム上の項目、および複数項目の部分失敗を実画面で確認すること。
- macOS 15 とそれ以降のバージョン差。

この作業環境では GUI アプリを起動していない。下の手順を使い、専用ヘッドレス VM または検証用 Mac で画面と動作を確認する。

## 撮影の手順

撮影は専用ヘッドレス VM のゲスト内で行う。ホストの画面にはアプリを表示しない。

### 検証用データ

1. ゲストで `~/dockstudio-drop-to-trash` を作る。
2. その中に `single.txt`、`multi-a.txt`、`multi-b.txt` を作り、各ファイルに復元確認用の短い内容を書く。
3. Dock Studio を起動する。通常の設定データを使う場合は、起動コマンドに `DOCKSTUDIO_DATA_DIR=<ゲスト内の設定ディレクトリ>` を指定する。空のディレクトリを指定すれば、既定のプロファイルを使える。
4. 設定で Custom Dock を表示し、ゴミ箱が Dock の末尾にあることを確認する。

### 操作

1. `single.txt` を Dock のゴミ箱へドロップする。元の場所から消え、Finder のゴミ箱に現れることを確認する。
2. Finder でゴミ箱を開き、`single.txt` の「戻す」を選ぶ。元のディレクトリに復元されることを確認する。
3. `multi-a.txt` と `multi-b.txt` をまとめてゴミ箱へドロップし、両方がゴミ箱に入ることを確認する。両方を「戻す」で復元する。
4. ゲスト内で安全に作ったアクセス不可の項目、ロック済み項目、または読み取り専用ディスクイメージ上の項目を試す。失敗項目名とエラーが表示され、成功した項目はゴミ箱へ移動することを確認する。アクセス権やロック状態は検証後に元へ戻す。
5. ゲストの一時ファイルをすべて元の状態に戻し、Dock Studio を終了する。

### 期待する結果と撮影するもの

- ドロップした項目だけがゴミ箱へ移り、永久削除されない。
- 「戻す」で元の場所へ戻る。
- 一部の項目が失敗した場合、失敗名と理由が表示され、残りの項目は処理される。
- 画像は、ドロップ前の Dock、移動後の Finder ゴミ箱、復元後の元ディレクトリ、失敗時のエラー表示を撮る。
- 動画は、単一ファイルのドロップ、ゴミ箱内の確認、「戻す」による復元までを撮る。
