# Dock の外へドラッグして参照を取り外す

## 仕様

Custom Dock の保持されている項目を、Dock の外までドラッグして離すと、使用中のプロファイルから参照を取り除く。保存処理は、右クリックメニューと同じ `DockStore.removeFromActiveProfile(_:)`（`removeSavedItem(_:fromProfile:)`）を使う。新しい保存処理は作っていない。

ドラッグ中の項目は、ポインタに追従する。Dock の枠から12pt以上外に出ると、項目が半透明になり、項目の上に「取り外す」の予告が出る。この状態で離すと取り外す。

次の場合は取り外さない。

- 枠の中、または枠から12pt未満の範囲で離した。
- 外に出た後、枠の中へ戻して離した。予告は戻ると消える。
- ドラッグがキャンセルされた（`onEnded` が呼ばれずジェスチャが終わった）。
- 項目を6pt動かす前に離した。通常のクリックとして項目を開く。

元のアプリやファイルには触れない。「実行中のアプリを表示」で一時的に出ている項目は、保持されていないため（`store.isPinned`）ドラッグの対象にしない。保存先が読み取り専用のときも対象にしない。

標準 Dock の煙のアニメーションは、受け入れ条件にないため実装していない。

実装は `DockStudio/DockDragOutRemoval.swift` に置いた。枠の外かどうかの判定は、画面から独立した `DockDragOutRemoval.isOutside(location:barSize:margin:)` にした。`DockBar` には、枠の寸法の取得と、`dockItem` への修飾の追加だけを足している。ドラッグには `onDrag` ではなく `DragGesture` を使った。`onDrag` は離した場所と終了を知らせないため。

## 未検証

実際のドラッグ操作は、どれも確認していない。撮影の担当が次の点を確認する。

- `highPriorityGesture` のドラッグが、`Button` のクリックと競合しないか。ドラッグ後に離した位置が元の項目の上でも、項目が開かないか。
- デスクトップ用パネルの Dock で、枠の外（パネルの窓の外）まで追従し、離した位置が正しく判定されるか。項目の表示は窓の範囲で切れる可能性がある。
- 「使用していないときに隠す」が有効なとき、ドラッグで枠の外に出た時点で Dock が隠れ、ジェスチャが途切れないか。
- Esc やウィンドウの非アクティブ化によるキャンセルで、取り外されないか。
- 左右配置、複数プロファイル、macOS 15〜25。

## 撮影の手順

撮影の専任の担当が、この節だけで実施する。

### 起動

検証用データに、次の6項目を持つプロファイルを1つ作る（`profiles.json`、`DOCKSTUDIO_DATA_DIR` で指すディレクトリ）。

- Finder、Safari、Mail、Terminal、Calendar（アプリ）
- Downloads（フォルダ）

設定は、モードを「Custom Dock」、「実行中のアプリを表示」を有効にする。起動は次の形にする。

```
DOCKSTUDIO_DATA_DIR=<検証用ディレクトリ> open -a DockStudio
```

### 操作

1. Mail を、枠の外（Dock の上側で、枠から50pt以上離れた位置）までドラッグし、離さずに止める。「取り外す」の予告と半透明の項目を撮る。
2. そのまま枠の中へ戻す。予告が消えることを撮る。離しても Mail が残る。
3. もう一度外までドラッグして、離す。Mail が消え、Dock が詰まり、「Mail を Dock から取り外しました」が出る。
4. アプリを再起動し、Mail が戻らないことと、ゲストの `/System/Applications/Mail.app` が残ることを確認する。
5. 実行中の Calculator など、保持されていない項目をドラッグして外で離す。何も起きない。
6. Terminal を、動かさずにクリックする。通常どおり起動する。
7. 外までドラッグした状態で Esc を押す、または別のアプリをアクティブにして、離す。取り外されない。
