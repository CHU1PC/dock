# パネルの背景の左右の余白を、項目に合わせる

## 原因

背景（`DockBackdrop`）には、並びの方向の長さを指定していなかった（`DockStudio/CustomDockPreview.swift:145-147`、#214 の時点では厚みの方向だけ `frame` で指定していた）。そのため、背景は `DockBar` の幅いっぱいに広がっていた。`DockBar` の幅はウィンドウの長さで、`DockMetrics.length(for:)`（同 `1229` 行付近）が決める。この値には、項目に必要な長さのほかに、次の余白が含まれていた。

- 項目を並べる `ScrollView` の内側の `.padding(.horizontal, 12)`（`CustomDockPreview.swift:173`）。項目自身の左右 5pt と合わせて、先頭の項目の手前に 17pt 残る。
- ホバー拡大の余白 `iconSize × (拡大率 − 1) × 3`（`length(for:)` の `reserve`）。設定が拡大オンのときだけ加わる。
- 末尾の見込み分 `10 + 11`、先頭の `24`、下限 `max(220, …)`。

項目は `frame(minWidth:)` の中で中央に寄るので、余白は左右に均等に残り、アイコン 16 では背景の端と先頭の項目の間が標準 Dock よりずっと広くなった。ウィンドウの長さは、拡大したアイコンの余白としては必要な値なので、変えていない。

## ホバー拡大時に端の項目がはみ出す原因（#218）

#216 の背景の長さ（`DockMetrics.backdropLength`、`CustomDockPreview.swift` の `backdropLength`）は、拡大前の項目の長さに固定していた。一方、拡大中の内容は、`dockItem`（同 `329` 行付近）と `trashSection`（同 `534` 行付近）が `ItemIcon(size: displayIconSize * scale)` で描くので、`DockAppearance.scale(index:hovered:maximum:)` の分だけ並びが長くなる。拡大した並びは背景より長くなり、先頭と末尾の項目が背景の端の外に出た。

## 変更内容（#218）

- `DockBackdropFit.magnifiedLength(base:iconSize:scales:windowLength:)` を追加した。純粋な関数で、項目とゴミ箱ごとの拡大率から `iconSize × (拡大率 − 1)` の合計を求め、`base` に足す。合計が 0（ホバーなし、または拡大オフ）のときは `base` をそのまま返す。伸びた分は `max(base, windowLength)` を超えない。
- `DockMetrics.backdropLength` に `hoveredIndex`、`magnificationScale`、`windowLength` を足した（既定値は #216 と同じ結果になる）。拡大率は、描画と同じ `DockAppearance.scale` と同じ添字で求める。
- `DockBar` は、ホバー中の添字を背景の長さに渡す。背景の `frame` は既存の `.animation(motion, value: hovered)` の下にあるので、拡大の動きに合わせて滑らかに追従する。
- 下配置と左右配置は、同じ関数を使う（並びの方向の長さだけが違う）。ウィンドウの大きさ、操作領域、自動非表示は変えていない。

## 変更内容（#216）

- `DockStudio/Services/DockBackdropFit.swift` に `length(_:iconSize:axisPadding:vertical:)` を追加した。拡大前の項目の長さの合計に、先頭と末尾の余白を足す純粋な関数になる。
  - 項目の長さ: アイコン + 項目の余白 2 つ（左右配置は点の行 9pt を足す）。ゴミ箱は項目 1 つ分、区切り線は 30pt（アイコンサイズ変更のハンドル）、最小化したウインドウは 1 つあたり アイコン + 10pt。
  - 先頭と末尾の余白: 厚み側と同じ考え方で、項目の端から背景の端までを、下配置は 10pt、左右配置は 12pt にする。項目自身の余白は差し引く。
- `DockMetrics.backdropLength(for:iconSize:axisPadding:)` を追加した。スペーサー、区切りの線、時計、タイマーの長さは、既存の `length(for:)` の値に合わせた。
- `DockBar` の背景に `frame(maxWidth:)`（左右配置は `maxHeight:`）を足した。背景は項目の長さまで縮み、`DockBar` の幅より長くはならない。項目が多くてスクロールが要る場合は、従来どおり幅いっぱいになる。
- ウィンドウの大きさ、操作領域、自動非表示、ドラッグアウトの判定は変えていない。

## 自動テスト

`DockStudioTests/DockBackdropFitTests.swift` に追加した。

- 下配置で、アイコン 16、52、128 の背景の長さ（196、412、868）
- 左右配置で、スペーサー、時計、最小化したウインドウを含む長さ
- 項目の余白が縮んだ場合も、項目の端から背景の端までが変わらないこと
- 背景の長さが、拡大オンとオフのウィンドウの長さに収まること（下配置と左配置、アイコン 16、52、128）

#218 で追加した（同じファイル）:

- ホバーなし、拡大オフが、#216 の値と等しいこと
- 先頭、中央、末尾にホバーし、拡大率 1.45 と 2.0、アイコン 16、52、128 で、背景が拡大後の内容以上で、ウィンドウの長さ以下になること。ウィンドウが狭いときは、`base + 1` に収まること
- ストアの構成で、下配置と左配置の先頭、中央、ゴミ箱にホバーしたとき、背景が `base` より長く、ウィンドウの長さ以下になること

## 撮影の手順

見た目が変わる変更なので、撮影が必要になる。

1. `DOCKSTUDIO_DATA_DIR` に検証用のデータを置いて起動する。位置を下、背景を Apple Dock 以外の既定、項目をアプリ 5 件程度（時計とタイマーなし）にする。
2. アイコンサイズを 16、52、128 に変え、それぞれ「ホバー拡大」をオフにして、静止画を撮る。背景の左右の端と先頭、末尾の項目の間が、背景の上の余白（アイコンの上端から背景の上端まで 10pt）と同じ程度で、アイコン 16 で左右に広い空きが残らないことを確認する。
3. 時計、区切りの線（実行中のアプリや最近使ったアプリ）、ゴミ箱を含む構成でも撮り、項目が背景の外へ出ていないことを確認する。
4. 項目を増やして画面幅を超える構成（下配置）を撮る。背景が幅いっぱいになり、スクロールできることを確認する。
5. 「ホバー拡大」をオン（拡大率 1.45 と 2.0）にして、先頭（Finder）、中央、末尾（ゴミ箱）の項目の上にポインタを動かす動画を、アイコン 16、52、128 で撮る。拡大した端の項目が背景の端の内側に収まること、ホバーを外すと背景が拡大前の長さに戻ること、背景が急に飛ばず滑らかに伸び縮みすることを確認する。ホバーしたときの静止画も、先頭、中央、末尾で 1 枚ずつ撮る。
6. 左右配置でも、同じ手順で上下の余白と、先頭、中央、末尾へのホバーを確認する。アイコン 16、52、128 を撮る。

## 未検証

- 実際の画面での見え方は、実行して確認していない。標準 Dock との余白の比較は、撮影で確認する。
- ホバー拡大オンで端の項目を拡大したとき、背景が実際に内容を覆うか（#218 の修正）。計算と単体テストだけで、描画では確認していない。
- 拡大の動きに合わせた背景の追従の滑らかさ。`.animation(motion, value: hovered)` に乗せただけで、動画では確認していない。
- ゴミ箱の手前のハンドル（30pt）と、時計 135pt、タイマー 120pt の長さは、コードから計算した値で、描画した実寸とは照合していない。
- 最小化したウインドウが多い場合の見え方。
