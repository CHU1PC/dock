# パネルの背景の余白を、アイコンに合わせる

## 原因

下配置の背景の高さは `DockMetrics.barThickness`（`DockStudio/CustomDockPreview.swift`）が `max(アイコンサイズ, 54) + 30` で決めていた。54 は時計とタイマーのタイルの高さで、タイルが無い Dock でも下限として効いていた。アイコン 16 では、背景が 84pt になり、アイコンの上に約 49pt の空きが残った。ホバー拡大の余白は背景ではなくウィンドウ高（`DockMetrics.thickness`、`CustomDockWindowController.swift` の `update()`）が確保していて、背景の高さには含まれていなかった。

左右配置の背景の幅は `max(174, アイコンサイズ × 拡大率 + 32)` で、174 の下限と拡大率が効いていた。

## 変更内容

- `DockStudio/Services/DockBackdropFit.swift` を追加した。背景の厚みを、拡大前のアイコンと、タイルの有無から求める純粋な関数になる。
  - 下配置: 内容の高さ（アイコン + 実行中の点の行 9pt、タイルがあれば 54pt との大きい方）+ 上下 10pt ずつ。
  - 左右配置: 内容の幅（アイコン、タイルがあれば 140pt との大きい方）+ 左右 12pt ずつ。
- `DockMetrics.backdropThickness(for:)` を追加し、背景の `DockBackdrop` の枠だけをこれに切り替えた。
- ウィンドウの大きさ、操作領域（`interactionFrame`）、自動非表示、ドラッグアウトの判定には `barThickness` と `thickness` をそのまま使っていて、変えていない。ウィンドウは従来どおり大きく透明で、拡大したアイコンは背景の外へはみ出して表示される。
- `DockVerticalFit.swift` には触れていない。

背景の高さ（拡大なし、タイルなし）は次のとおりになる。

| アイコン | 変更前 | 変更後 |
| --- | --- | --- |
| 16 | 84 | 45 |
| 52 | 84 | 81 |
| 128 | 158 | 157 |

## 撮影の手順

見た目が変わる変更なので、撮影が必要になる。

1. `DOCKSTUDIO_DATA_DIR` に検証用のデータを置いて起動する。設定は、位置を下、背景を Apple Dock 以外の既定（`DockBackdrop` が見える背景）、項目をアプリ 5 件程度（時計とタイマーは入れない）にする。
2. アイコンサイズを 16、52、128 に変え、それぞれ「ホバー拡大」をオフとオンにする（計 6 通り）。
3. 拡大オフでは、静止画を撮る。背景がアイコンのすぐ周りに詰まり、上の余白が下の余白（点の行を含む約 19pt）より少し狭い程度になっていることを確認する。
4. 拡大オンでは、アイコンの上にポインタを動かす動画を撮る。拡大したアイコンが切れず、背景の上へはみ出して表示されることを確認する。
5. 期待する見え方: 変更前は 16 で上に約 49pt の空きがあったが、変更後は 10pt 前後になる。52 と 128 は、ほぼ変わらない。
6. 左右配置でも、同じ手順で幅を確認する（アイコン 16 で背景の幅が約 40pt になる）。

## 未検証

- 実際の画面での見え方、拡大したアイコンが切れないこと、自動非表示とホバーの挙動は、実行して確認していない。
- 左右配置では、拡大したアイコンが背景の中央から両側へ広がる。標準 Dock のように画面の内側へだけ広がる配置には、していない。
- 左右配置で、#210 の自動縮小によりアイコンが縮んだ場合も、背景の幅は設定したアイコンサイズから決まる。
