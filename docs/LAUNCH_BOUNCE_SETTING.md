# 起動時のアイコンのバウンド

## 仕様

設定画面の「Dock」の「動作」に、「起動中にアイコンを跳ねさせる」を追加した。有効にすると、Custom Dock のアイコンをクリックして未起動のアプリを開いたときに、そのアプリが起動を終えるまでアイコンが跳ねる。標準 Dock の「アプリケーションを開くときにアニメーションで知らせる」に対応する。

設定は `DockSettings.launchBounce` として保存し、全プロファイルに共通になる。設定を含むバックアップでも復元する。以前の保存データやバックアップに項目がない場合は、標準 Dock の既定に合わせて有効で読み込む。そのため、更新後は以前と違い、アプリの起動中にアイコンが跳ねる。

起動の状態は、Custom Dock から開始した未起動のアプリにだけ付ける。すでに起動しているアプリを開く操作では跳ねない。状態は次のいずれかで終わる。

- アプリの起動に失敗した。
- アプリが起動を終えた（`isFinishedLaunching`）、または終了した。
- 30秒が経った。

跳ねる向きは、下配置では上、左右配置では画面の内側になる。「アニメーションを減らす」（アプリの設定）または macOS の「視差効果を減らす」が有効なときは、動かさない。起動中を示す点や代替の表示は使わない。跳ねる処理は、起動中で、かつ有効なアイコンにだけ付ける。それ以外のアイコンには何も付けない。

## 検証

2026-10-17 に、以下を確認した。

| 項目 | 結果 |
| --- | --- |
| 自動テスト | 101件すべて成功した（`swift test`） |
| 古い保存データとバックアップ | 項目がなくても有効で読み込めた |
| 有効と無効 | 保存、再読込、バックアップ復元で保持された |
| 起動状態の終了 | 完了、失敗、30秒のタイムアウトで終わることを、状態の管理だけ確認した |
| Release ビルドと `build-for-testing` | 成功した |

GUI は macOS 26.6.2、1600×1000の専用ヘッドレス VM 内で確認した。ホストのデスクトップには、アプリや VM の画面を表示していない。`xcodebuild test` は、テストホストがホストの画面に出るため実行していない。

- 項目のない保存データで起動し、設定画面でスイッチが有効だった（[設定画面](media/launch-bounce-setting/settings-on.png)）。
- 有効で、Custom Dock の Calendar をクリックすると、録画した約8秒間は跳ね続けた。録画後の画面では、Calendar のウィンドウが出て起動の点が付き、アイコンは止まっていた（録画後の約10秒間に撮った3枚で位置が同じだった。止まった時刻は測っていない）。跳ね上がった瞬間は[静止画](media/launch-bounce-setting/bounce-on-midair.png)、動きは[動画](media/launch-bounce-setting/bounce-on.mp4)に残した。
- スイッチを無効にして保存ファイルが `launchBounce: false` になったことを確認した（[設定画面](media/launch-bounce-setting/settings-off.png)）。同じ操作で Calendar は起動したが、アイコンは動かなかった（[動画](media/launch-bounce-setting/bounce-off.mp4)）。
- 有効に戻し、「アニメーションを減らす」を有効にして同じ操作をした。アイコンは動かなかった（[設定画面](media/launch-bounce-setting/settings-reduce-motion.png)、[動画](media/launch-bounce-setting/bounce-reduce-motion.mp4)）。

- 修正後のビルドで、Dock が表示されただけでは跳ねないことを確認した。「デスクトップに Dock を表示」「デスクトップの Dock を隠す」「デスクトップに Dock を表示」の順に押し、表示、非表示、再表示を録画した（[動画](media/launch-bounce-setting/dock-show-no-bounce.mp4)）。どのフレームでも、アイコンは跳ねなかった。
- 修正後のビルドで、有効、無効、アニメーションを減らす有効の3つを撮り直した。有効では Calendar のアイコンだけが跳ね、他のアイコンは動かなかった。無効と、アニメーションを減らすでは動かなかった。

[設定画面](media/launch-bounce-setting/settings-on.png)の3枚は、修正前のビルドで撮った。設定の説明文が、現在の文言と異なる。

動画は、VNC で取得した920×360の連続画像から、撮影時刻の間隔を維持して15fpsに変換した。実際の取得は約9fpsで、倍速にはしていない。VM の撮影であり、実機での描画性能の測定ではない。各動画は約8秒で、開始から約1.5秒後に操作した。

検証した実行ファイルの SHA-256 は `bc92ec509a137b5f01441eec8883fd17dc16605061b42d60bfa614b028db5a66` になる。

## 未検証

- 標準 Dock のバウンドとの差。高さ、周期、回数、アプリが最初のウィンドウを出すまで続くかを、標準 Dock と並べて測っていない。このバウンドの高さ（アイコンの半分、最大28pt）と周期（約1.1秒）は、標準 Dock を観察して決めた値ではない。
- 起動の終わりの判定は `isFinishedLaunching` と30秒の上限による。起動中の跳ねが、録画後に止まっていたことだけ確認した。完了の判定が標準 Dock と一致するかは未確認になる。
- 無効と、アニメーションを減らすの動画は、デスクトップ用パネルが管理画面の Dock と重なった状態で撮った。管理画面側の Calendar のアイコンは一部が隠れている。パネルの Calendar のアイコンが動かないことは見えているが、隠れた側の確認は十分とは言えない。
- 自動非表示からの復帰（ポインタを画面端に置く操作）では、跳ねないことを撮っていない。管理画面のボタンによる表示、非表示だけを確認した。プロファイルの切り替えも撮っていない。
- macOS の「視差効果を減らす」は VM では切り替えていない。アプリの「アニメーションを減らす」だけ確認した。
- 左右配置での跳ねる向き。
- すでに起動しているアプリを開くときに跳ねないこと（実画面）。
- 起動に失敗するアプリでの実画面の挙動（状態の終了はテストで確認した）。
- macOS 15〜25 と実機。
