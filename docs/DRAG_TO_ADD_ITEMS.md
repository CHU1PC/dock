# ドラッグで項目を Dock に追加する

## 仕様

Finder からアプリ、ファイル、フォルダをドラッグして Custom Dock にドロップすると、有効なプロファイルに追加される。複数項目を一度にドロップできる。ドラッグ中は、挿入位置に縦または横の線を表示し、離した位置に項目を挿入する。位置は、ポインタを各項目の中点と順に比べて決める。ポインタが項目の中点より前なら、その項目の前に入り、すべての項目の中点を過ぎていれば末尾になる。線は、その位置の隣の項目の高さ（縦並びでは幅）に合わせて描く。

- ドロップの操作は「コピー」として受け付ける。元のファイルは移動も複製もしない。保存するのは参照（ファイル URL）だけになる。
- 追加した項目は、その場で保存済みのプロファイルに書き込む。再起動後も順序と対象が復元される。編集中の下書きがある場合は、ドロップ位置の直前にある保存済みの項目の後ろに、項目を足す。その項目が下書きで削除されていれば下書きの末尾に、直前の項目がない（先頭）ならば下書きの先頭に入れる。他の編集内容は保持する。
- 種類はドロップした対象から決める。拡張子が `.app` のディレクトリはアプリ、それ以外のディレクトリはフォルダ、それ以外はファイルにする。
- 追加前に、項目を開くときと同じ `ItemLaunchPolicy` で検証する。スクリプトや実行ファイル、アプリとして不正な `.app`、存在しない対象、ファイル URL ではない対象は追加しない。受け付けられる項目だけを追加し、拒否した項目名をアラートで示す。
- 挿入位置は表示中の項目の並びで決める。一時表示の実行中アプリの位置に落とした場合は、線がその位置に出るが、項目は保存済みの項目の末尾に入る。線の位置と挿入先がずれる（未対応）。
- すべての項目の位置を測り終えるまでは、ドロップを受け付けない。
- 保存先を読み込めずに読み取り専用になっている間は、ドロップを受け付けない。
- 管理画面内のプレビューも、デスクトップ用パネルの Dock と同じ `DockBar` なので、ドロップできるはずである。ただし、プレビューへのドロップは撮影も確認もしていない。

実装は `DockBar` の `onDrop`（`DockDropDelegate`）、挿入位置の計算 `DockDropInsertion`、`DockStore.addDroppedItems(_:at:)` になる。項目の位置は、ホバー名の表示と共通の `DockItemFrames` で、`DockBar` の座標系の矩形として持つ。

## 検証

### 自動テスト

`DropDockItemsTests` の10件を追加した。ホストで `swift test` を実行し、全115件が成功した。

| 項目 | 結果 |
| --- | --- |
| ファイル、フォルダ、ファイルの順に位置1へ挿入 | 指定位置に順序どおり入り、前後の既存項目は変わらなかった |
| 保存と再読み込み | 順序と対象 URL が復元された |
| 元ファイルとフォルダ | 内容と存在が変わらなかった |
| 範囲外の位置（負数と過大） | 先頭と末尾に丸められた |
| スクリプト、偽の `.app`、存在しない対象、Web の URL | 4件を拒否し、通常のファイルだけ追加された |
| 正しい `.app` | アプリとして追加された |
| 読み取り専用の保存先 | 追加されず、元のファイルも変わらなかった |
| 未保存の下書き | 下書きの名前を保持し、項目が下書きにも入った |
| 下書きで先頭の2項目を削除した状態 | ドロップ位置の直前にある保存済みの項目の後ろに入った。その項目も削除済みなら下書きの末尾、先頭なら下書きの先頭に入った |
| 挿入位置の計算 | 横並びと縦並び、空の Dock、末尾を確認した |

Release ビルドと `xcodebuild build-for-testing` も成功した。`xcodebuild test` は、テストホストがホストの画面に出るため実行していない。

### 実画面（専用ヘッドレス VM）

以下の画像と動画は、コミット `8356b8c` 時点のビルドで撮影した。その後、項目の位置の取得を `DockItemFrames` に統一し、位置が未計測の間はドロップを拒否し、線の縦位置を隣の項目の矩形から求める変更を入れた。この変更後のビルドは、VM で再確認できていない。専用 VM のロックを45分待ったが、他の作業が保持し続けたため取れなかった。この変更は、ホストのビルドと自動テストだけで確認した。

macOS 26.6.2、1600×1000の専用ヘッドレス VM で確認した。ホストのデスクトップには、アプリや VM の画面を表示していない。ドラッグは、ゲスト内で CGEvent を使うツールで合成した（ボタン押下、30段階の移動、保持、離す）。検証したビルドの実行ファイルの SHA-256 は `801863e2b9bb6771c9091e52a6ad9366afda392927de98fec56c7c9d4f116721` で、ホストの最終 Release ビルドと一致した。

ゲストの Finder で、5項目（Calculator.app のコピー、plan.md、setup.sh、メモ.txt、フォルダ「資料」）をすべて選択し、1つをデスクトップ用パネルの Dock へドラッグした。

- ドラッグ中、Dock の上に項目の境界を示す線が出て、ポインタの移動に追従した（[ドラッグ中](media/drag-to-add-items/dragging-insertion-indicator.jpg)）。
- Safari と Mail の間で離すと、Calculator、plan.md、メモ.txt、資料の4項目が、Safari の後ろに選択した順で入った。setup.sh は拒否され、「次の項目は Dock に追加できませんでした。setup.sh」のアラートが出た（[ドロップ直後](media/drag-to-add-items/after-drop-rejected-alert.jpg)）。
- 保存ファイルの項目は10件になり、順序は Finder、Safari、Calculator、plan.md、メモ.txt、資料、Mail…だった（[保存内容](media/drag-to-add-items/profile-after-drop.txt)）。元のフォルダには5項目がそのまま残った。
- アプリを終了して再起動すると、同じ順序で表示された（[再起動後](media/drag-to-add-items/after-relaunch.jpg)）。
- 動画は[ドロップの一連の操作](media/drag-to-add-items/drop-multiple-items.mp4)と、[Dock の上で保持した後に Finder のウインドウへ戻して離す操作](media/drag-to-add-items/drag-cancel.mp4)を保存した。後者では項目が追加されず、線も残らなかった。動画は撮影時刻の間隔を維持して12fpsに変換し、倍速にはしていない。VM の撮影であり、描画性能の測定ではない。

### 検証中に直した問題

最初のビルドでは、ドロップした後も挿入位置の線が消えなかった。ドロップ後に位置の更新が届いても線を再表示しないようにして修正し、最終ビルドで、ドロップ後と取り消し後に線が消えることを確認した。

## 未検証

| 項目 | 状況 |
| --- | --- |
| 実際のポインタとトラックパッドによるドラッグ | CGEvent の合成であり、実機の入力との差は確認していない |
| 上記の変更後のビルドでの、線の描画、ホバー名の表示、ドロップ | VM で未確認。再確認が必要になる |
| Dock 左右配置、自動非表示中のドロップ | 下端配置の常時表示だけを確認した。自動非表示で隠れている間は、画面端の反応領域が当たるかを確認していない |
| 管理画面内のプレビューへのドロップ | 同じ `DockBar` だが、VM では撮影していない |
| 項目が多く Dock がスクロールする状態 | 線の位置は未確認 |
| Finder 以外の送り元、デスクトップのアイコン、アプリのウインドウのプロキシアイコン | 未確認 |
| Dock の項目同士の並べ替え、Dock の外へのドラッグ | 範囲外であり、実装していない |
| 同じアプリの重複 | 標準 Dock と異なり、重複を検出せずに追加する |
| macOS 15〜25、複数画面、Intel Mac、実機での描画 | 今回の GUI 検証には含まない |
| VoiceOver、キーボードだけでの追加 | 対象外 |
| 受け入れ条件「挿入位置を示して」の標準 Dock との見た目の一致 | 線による表示であり、標準 Dock のように項目が左右へ開く動きは実装していない |
