# SwiftUI 版の検証結果

## 対象と条件

2026-10-17 に、SwiftUI と AppKit の実装を macOS 26.5.2、Apple M4 Pro、24 GB、Xcode 26.6 で確認した。最小対象は macOS 15 である。Finder、Safari、Mail、Terminal の4個だけを持つ検証用プロファイルを使用した。ユーザーの通常の設定から分離した保存先を使い、Apple Dock の設定は変更していない。

Custom Dock、設定画面、プロファイル編集画面は SwiftUI で動作する。GPUI プロセスや Rust ヘルパーは起動していない。比較のために以前取得した資料は[技術比較](FRAMEWORK_COMPARISON.md)に残し、今回の性能測定とは区別する。

## ビルドとテスト

```text
xcodebuild -project DockStudio.xcodeproj -scheme DockStudio -configuration Release   -derivedDataPath /tmp/dockstudio-swiftui-appearance-derived CODE_SIGNING_ALLOWED=NO build
** BUILD SUCCEEDED **

swift test --scratch-path /tmp/dockstudio-swiftui-appearance-tests
Executed 72 tests, with 0 failures (0 unexpected)
```

新しい外観テスト14件を含む。既存の58件も成功した。外観の保存と再読み込み、旧ファイルの既定値、未知キー、破損、無効な数値、保存失敗時の復元、デバウンス、別プロセスの同時保存、背景画像の縮小と掃除、保存先の移動、倍率、負の画面座標、縦配置の寸法、実際の CGContext による透明度と白黒変換を確認した。

AppIntents を使っていないため、Xcode の metadata extraction skipped 警告は残る。Swift 6 の Sendable に関する警告は、イベントそのものを MainActor.assumeIsolated の戻り値にせず、処理済みかどうかだけを返す形にして除いた。プロジェクトの言語モードは引き続き Swift 5 である。

## 実機で確認した内容

| 内容 | 結果 |
|---|---|
| Dock の表示、管理画面を閉じた後の常駐、管理画面の再表示 | 動作した |
| ホバーと隣接アイコンの拡大、名前の表示、起動中の点 | 実表示と動画で確認した |
| 自動非表示と下端からの復帰 | 画面の実際の下端へ移動して復帰した。動画に退避と再表示を収録した |
| 右クリックのメニュー | 「開く」と「Finder で表示」が表示され、ポインタを外して1秒以上待っても操作できた。Escape で閉じた後に自動非表示も復帰した |
| キーボード操作 | メニューバーから Dock を選び、Tab でフォーカスを移動できた。Shift+Tab で戻り、Return で Finder を起動した |
| 日本語入力 | プロファイル名にローマ字で nihongo と入力し、変換と確定を行った。「日本語」として保存でき、再起動後も残った |
| 背景 | システム素材、単色、画像、完全透明を切り替えて実表示を確認した。システム素材のぼかしを切ると単色になった |
| 画像の取り込み | ネイティブのファイル選択で、合成したグラデーション画像を選んだ。管理フォルダの UUID 名 PNG にコピーされ、アプリ再起動後も使えた |
| アイコン | 通常、白黒、透けた単色のガラス調を実表示で確認した |
| 左と右の縦配置 | 76pt、拡大率2倍で Finder と隣接アイコンを表示し、横方向に切れないことを確認した。画像も保存した |
| アクセシビリティ情報 | AXAttributedDescription から Finder の名前と起動中状態、他の項目の名前を読めた。Orca の簡略ツリーには、この属性が表示されない場合があった |
| サイズと拡大率の操作 | スライダーの AXIncrement と AXDecrement を使い、設定ファイルへの反映を確認した。単に AX の value を書き換えただけの結果は検証に採用していない |

背景とアイコンの画面は、[画像フォルダ](media/swiftui-appearance/)に保存した。動画は [dock-motion.mp4](media/swiftui-appearance/dock-motion.mp4) にある。透明部分は、単独ウィンドウの動画では黒く表示される。デスクトップ全体や他のアプリの内容は録画に含めていない。

## 実操作で見つけた問題と修正

当初、画面端で復帰した後にホバーが反応しない場面があり、SwiftUI のアニメーションが原因という仮説を調べた。状態の記録では折りたたみと復帰が正常だった。実際の表示領域を確認すると、標準の Apple Dock が Custom Dock の上に現れて操作を受けていた。

Custom Dock のウィンドウレベルを標準 Dock より1つ上にした。マウスの移動イベントも明示的に受け取るようにした。修正後は、同じ下端からの復帰とホバーを動画で確認した。SwiftUI のアニメーションを原因とした仮説は採用していない。診断用の出力と試した別方式のアニメーションは、製品コードに残していない。

## 性能

Release ビルドの同じプロセスを順に測った。システム素材、不透明度55%、通常アイコン、52pt、拡大1.45倍、起動中の点を有効にした。性能測定では自動非表示を無効にした。測定前に各画面と加工を表示しているため、キャッシュが温まった状態である。

| 状態 | 秒数 | physical footprint 中央値 | RSS 中央値 | CPU |
|---|---:|---:|---:|---:|
| 外観の管理画面と Dock を表示 | 29.11 | 52.14 MiB | 118.42 MiB | 0.0101% |
| 管理画面を閉じて Dock を常駐 | 45.17 | 56.74 MiB | 111.69 MiB | 0.0264% |
| 同じ状態で連続ホバー | 20.05 | 56.78 MiB | 106.19 MiB | 0.7896% |

CPU は、プロセスの user と system の CPU 時間増分を実時間で割った値で、1コアを100%とする。メモリは proc_pid_rusage の physical footprint と RSS を区別している。管理画面の系列は、閉じる操作が測定に入らないよう最後のサンプルを除いた。Dock 常駐時に管理画面より footprint が高いのは、測定順序と保持される描画資源を含む結果であり、画面を閉じれば必ずメモリが減るという評価には使わない。

[測定の生データと集計](verification/swiftui-appearance/)を保存した。録画中には測っていない。GPU 全体、消費電力、フレーム落ちの測定ではない。以前の約38 MiBの結果は、拡張前の別実装と条件の結果なので、今回の完成状態の値として扱わない。

## 残る確認と制約

- macOS 15〜25 の実表示、Intel Mac、ディスプレイの抜き差し、複数 Spaces とフルスクリーンの組み合わせは未検証である。
- VoiceOver による全操作の読み上げは未検証である。キーボードと AX 情報の取得までを確認した。
- 透過した余白の背面クリックは、実際に背面へ別のウィンドウが重なる環境で継続確認が必要である。今回の自動操作では別アプリが背面にあり、アプリ内のボタンの切り替えを確認できなかった。パネルの ignore 判定と画面端の幾何は実装したが、この確認を合格とは数えていない。
- メニュー追跡通知が対にならず残る現象は未再現である。理由なくタイムアウトで解除する処理は追加していない。
- 外観は全プロファイル共通である。現在のプロファイル書き出しは、外観と背景画像を含めない。
- 今回の PR は、SwiftUI で UI 改善を続けるための実装である。Apple Dock の配置書き換え、集中モード連携、外部サービス、一般配布の署名と公証など、アプリ全体の残りの作業を完了したものではない。
