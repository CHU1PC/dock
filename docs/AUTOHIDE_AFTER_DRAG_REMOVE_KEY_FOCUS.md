# ドラッグ取り外し後に残るキーウィンドウ状態を解除する

## 変更内容

自動非表示中の Dock 項目を外へドラッグして取り外した後、パネルが隠れない問題に対応する。左ボタンを離してドラッグ状態を終了するとき、Custom Dock パネルがキーウィンドウならキー状態も解除し、自動非表示の判定を再開する。

PR #192 はマウスアップでドラッグ状態を終了させる処理を追加したが、パネルのキーウィンドウ状態はそのまま残していた。`CustomDockWindowController.updateVisibility()` は `panel.isKeyWindow` を操作中として扱うため、ドラッグ状態が終わっても自動非表示が抑止され続ける。TextEdit のフォーカス枠が残った観察は、このキー状態が残る原因と整合する。Accessibility 案内ウィンドウの影響を含む実画面での再確認は行っていない。

## 仕様判断

マウスでドラッグを完了した後は、キーボードフォーカスのためにパネルを表示し続けない。マウスアップ時にパネルがキーウィンドウの場合だけ `leaveKeyboard()` を呼び、他のドラッグ終了処理や非キー状態には変更を加えない。

## 受け入れ条件との対応

| 条件 | 状況 | 根拠 |
|---|---|---|
| ドラッグ取り外し後、通常の待機時間を経て Dock が隠れる | 一部のみ | キー状態を解除する判定と、自動非表示状態の単体テストのみ。実画面は未確認 |

3. Calculator を Dock の外の y=300 までドラッグして離す。
4. 項目が取り外された後、通常の自動非表示待機を経て Dock が隠れることを確認する。
