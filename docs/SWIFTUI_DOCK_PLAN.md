# SwiftUI で Dock の実装を進める計画

## 決定と理由

2026-10-17 に、加藤さんが、アプリ全体の完成までは SwiftUI と AppKit で実装を進めると決定した。Custom Dock、設定画面、プロファイル編集画面は SwiftUI で進める。ウィンドウ、画面端の判定、背景素材などの macOS 連携には AppKit を使う。

比較検証では、4 個のアプリアイコンを表示して管理画面を閉じた状態で、SwiftUI が約 38 MiB、GPUI と Swift ヘルパーの合計が約 180 MiB を使った。GPUI の拡大と起動中表示を無効にしても差が残った。GPUI の画面内のアクセシビリティ情報の不足も確認した。[比較報告](FRAMEWORK_COMPARISON.md)に条件と限界を記録している。

この結果は現在の実装の比較であり、GPUI 一般の性能を否定するものではない。GPUI の全面移行を進める以前の方針は、今回の決定で保留になった。PR #3 と GPUI の試作は、将来の比較材料として残す。GPUI の実装を main に取り込んでから SwiftUI に戻す手順は取らない。

## 製品の目標

現在の Mac の Apple Dock に近い外観と操作感を持ち、背景とアイコンを自分で設定できる Custom Dock を作る。設定画面とプロファイル編集画面は、承認済みの画面構成を基に拡張する。

時計や集中タイマーは既存の任意項目として扱う。今回の実装の中心は Dock の見た目と操作であり、追加のウィジェット開発は含めない。

## 次の実装範囲

| 順序 | 内容 | 完了条件 |
|---|---|---|
| 1 | Dock の余白、角丸、輪郭、影を整える。ホバー拡大、隣接アイコンの拡大、名前の表示、起動中の点を作る | 現在の Apple Dock と並べて確認できる。拡大によって表示位置が跳ねたり、アイコンが欠けたりしない |
| 2 | 自動非表示と再表示の動きを整える。画面端と透過部分の操作判定を扱う | ポインタで再表示できる。右クリックや項目の操作中に隠れない。余白が背面の操作を妨げない |
| 3 | Dock の背景にシステム素材、単色、画像、完全透明を用意する。色、不透明度、ぼかしを設定できるようにする | デスクトップの壁紙を変更せず、Dock 自体の背景だけが変わる。再起動後も設定が残る |
| 4 | アイコンを通常、白黒、元のアイコンを透けた単色にするガラス調から選べるようにする | 元のアイコンと透過部分を保ち、選択した加工を反映できる。元のアプリのアイコンファイルを変更しない |
| 5 | 設定画面に外観の操作を追加し、実機確認、性能測定、レビューを行う | 下記の確認条件を満たし、画面と操作の証拠を PR 本文で確認できる |

SwiftUI の View と既存の Store を基にする。GPUI のウィンドウや Swift ヘルパーを、SwiftUI 版の実行時依存には追加しない。既存のプロファイル、下書き、取り込みと書き出しを保護する。外観設定の保存方法は既存データと互換性を保つ形にする。

## 実装後の確認条件

- アプリの起動、項目の起動、プロファイル切り替え、管理画面を閉じた後の常駐を実際に確認する。
- ホバー拡大、起動中の点、自動非表示、再表示、右クリックを実操作で確認する。
- 背景とアイコンの各設定を、Dock の実表示と再起動後の状態で確認する。
- 日本語入力、キーボード操作、画面内のアクセシビリティ情報を確認する。
- 保存失敗や破損した設定で、元のプロファイルを上書きしないことを確認する。
- Release ビルドで、管理画面表示、Dock 常駐、ホバー時の CPU とメモリを測る。測定は検証用プロセスの終了を確認した上で順番に行う。
- コードの変更を Sonnet に 1 回レビューしてもらい、指摘にはすべて対応する。未解決の項目は理由とともに記録する。
- PR 本文に変更した画面のスクリーンショットを掲載する。ホバーと自動非表示は実操作の動画で示す。
- PR の作成または更新で止める。内容の確認後に明示的なマージ指示が来るまで、GitHub の PR はマージしない。

macOS 15、Intel Mac、ディスプレイの抜き差しなど、手元で実施できない確認は未検証として区別する。一般配布までに必要な確認から外したことにはしない。

## GPUI を再検討する条件

予定するアプリ全体の実装と必要な検証を終えた後に、GPUI を再検討する。今回の Dock と外観設定は、アプリ完成までの途中工程として扱う。完成までは SwiftUI と AppKit の構成で開発を続ける。同じ機能、同じアイコン、同じ表示条件に揃え、Release ビルドで比較する。GPUI は Swift ヘルパーも含めて測る。

完成までに性能や表現の問題が出た場合は、SwiftUI と AppKit の構成で解決し、その結果を記録する。CPU とメモリだけでなく、入力から表示までの応答時間、フレーム落ち、アクセシビリティ、保守負担も判断材料にする。GPU 全体の評価方法は、WindowServer の合成処理も考慮して整理する。

SwiftUI が要件を満たしている場合は、フレームワークの名称だけを理由に再移行しない。GPUI の試作で得た外観や操作の知見は、SwiftUI 版の改善にも使う。

## 現在の進捗

SwiftUI と AppKit で、Dock の拡大、起動中表示、自動非表示、背景とアイコンの加工設定を実装した。設定画面とプロファイル編集画面は SwiftUI の構成を維持した。比較資料と、PR を勝手にマージしない規則も引き継いだ。レビューの全項目への対応は[対応表](SWIFTUI_REVIEW_FIXES.md)に記録している。実機確認と性能測定の条件は[検証報告](SWIFTUI_VERIFICATION.md)に記録する。これはアプリ全体の完成を意味しない。
