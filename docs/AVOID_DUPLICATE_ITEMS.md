# 同じ項目の重複追加を避ける

## 仕様

ドロップによる追加と、プロファイル編集の「アプリ…」「フォルダ…」「ファイル…」の両方で、すでにある項目と同じ項目を追加しない。避けた項目は、`DockStore.status` に「○○ は既に Dock にあるため、追加しませんでした」と出す。同じ操作の中に同じ項目が複数あるときは、最初の1つだけを追加する。

重複の判定は `DuplicateItemPolicy`（`DockStudio/Store/DuplicateItemPolicy.swift`）にまとめた。対象の種類は `deduplicatedKinds` だけで決まり、現在はアプリ、フォルダ、ファイルにしている（Refs #84 で、フォルダとファイルを加えた）。アプリは `DockItem.applicationIdentity`（バンドル ID、無ければ実体のパス）で比べる。フォルダとファイルは、シンボリックリンクを解決したパスで比べる。別のフォルダにある同名のファイルは、重複としない。

ドロップでは、保存済みのプロファイルと、未保存の下書きの両方を既存の項目として扱う。「ファイルを選んで追加」は、編集中のプロファイル（下書きを含む）を既存の項目として扱う。

既存のプロファイルにある重複は消さない。保存データの形式は変えておらず、重複を含む古い保存データも、そのまま読み込める。

## 未検証

標準 Dock が、UI のドラッグで、アプリ、フォルダ、ファイルのそれぞれの重複をどう扱うかは、確認できていない（標準 Dock は合成したドラッグを受け付けない。上の「実画面の確認」を参照）。`defaults` で `persistent-apps` に同じアプリを2件書くと、標準 Dock は2件とも並べた（#84 のコメント）。ただし、これは UI の挙動ではない。3種類すべてを対象にしたのは、確認できないために選んだ保守的な暫定の判断になる。撮影の担当が、下の手順の「標準 Dock の確認」で挙動を記録し、結果が違えば `deduplicatedKinds` を直す。

利用者への通知は `status` に入れただけで、画面のどこにどう見えるかは未確認になる。

## 実画面の確認（専用ヘッドレス VM）

2026-10-18 に、コミット `ce66c90` の Release ビルドを macOS 26.6.2 の専用ヘッドレス VM で確認した。実行ファイルの SHA-256 は、ホストとゲストで `ceb40da6e9ee0525306703848901b8bf7621bcd81c1687cbdd00dad1c0a2e11e` と一致した。空のディレクトリを `DOCKSTUDIO_DATA_DIR` に指定して起動した（ゲストの言語は日本語で、既定のプロファイル「仕事」から始まる）。ドラッグはゲスト内の CGEvent で合成した。

確認できたこと:

- Finder の Applications から Calculator をデスクトップ用パネルへドロップすると、1 つ追加された。同じ Calculator をもう一度ドロップしても、追加されなかった。保存ファイルの「仕事」は、Finder、Safari、メール、ターミナル、Calculator、スペーサーで、Calculator は 1 件だった（[profiles-after-two-drops.json](media/avoid-duplicate-items/profiles-after-two-drops.json)、[動画](media/avoid-duplicate-items/drop-twice-same-app.mp4)、[after-two-drops.jpg](media/avoid-duplicate-items/after-two-drops.jpg)）。

確認できなかったこと:

- **標準 Dock の重複の扱いは、確認できなかった**（[standard-dock-attempt.txt](media/avoid-duplicate-items/standard-dock-attempt.txt)）。合成したドラッグでは、Calculator が標準 Dock に追加されなかった（`persistent-apps` は 18 件のまま）。アプリ、フォルダ、ファイルのどれも、標準 Dock の結果を記録できていない。このため `deduplicatedKinds` をアプリだけにした判断の根拠は、まだ得られていない。
- 重複を避けたときの通知（「○○ は既に Dock にあるため、追加しませんでした」）の文言は、画像で確認できなかった。Finder のウィンドウが、状態の表示を隠した。
- 「アプリ…」での重複の確認（手順 4）は、撮影していない。
- 撮影後、ゲストの標準 Dock の設定は、`defaults import` で元に戻した。

`DuplicateItemTests` は、次を縛る。判定そのもの（`DuplicateItemPolicy.split`）は `DuplicateItemPolicyTests` が、同じアプリ、同じフォルダ、別フォルダの同名ファイル、シンボリックリンク、既存の重複、混在で縛る。

- 同じアプリを2回ドロップしても1つだけになり、通知が出る。
- 1回のドロップに同じアプリが2つあると、1つだけ追加される。
- 下書きにあるアプリは、ドロップで追加されない。
- 「アプリ…」で選んだ同じアプリは、既存の項目と、同じ選択の中の重複の両方が避けられる。
- 同じファイルと同じフォルダは、2回ドロップしても1つだけになる。
- 1回のドロップに既存の項目と新しい項目が混ざると、新しい項目だけが追加され、既存の項目が通知される。
- 「ファイル…」で選んだ同じファイルは避けられる。
- プロファイルに最初からある重複は、残る。

## 撮影の手順

見た目が変わるのは、重複を避けたときの通知だけになる。

### 標準 Dock の確認

専用のヘッドレス VM で、標準 Dock に次を行い、結果を `docs/media/avoid-duplicate-items/` に記録する。

1. すでに Dock にあるアプリを、Finder からもう一度 Dock にドラッグする。
2. Dock にあるフォルダを、もう一度ドラッグする。
3. Dock にあるファイルを、もう一度ドラッグする。

それぞれ、追加された、無視された、位置が動いただけ、のどれになるかを書く。

### アプリでの確認

1. `DOCKSTUDIO_DATA_DIR` に、空のディレクトリを渡して起動する。既定のプロファイルで始まる。
2. ゲストの `/Applications` にあるアプリ（例: Calculator）を、Dock の端にドロップする。1つ追加される。
3. 同じアプリをもう一度ドロップする。追加されず、通知が出る。
4. 設定画面のプロファイル編集で「アプリ…」から同じアプリを選ぶ。追加されず、通知が出る。
5. フォルダとファイルでも、手順2と3を行う。標準 Dock が重複を許した場合は、`deduplicatedKinds` から外す。
